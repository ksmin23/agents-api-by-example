# 실습 안내와 검증 범위

각 노트북은 새 커널에서 위에서 아래로 실행합니다. 설치·커널·데이터 경로는 [환경 준비와 실행 점검](../notebooks/setup.ipynb), API 키·모델 설정과 첫 호출은 [빠른 시작](../notebooks/quickstart.ipynb)을 참고하세요.

## 공통 학습 경로와 장별 연결

같은 CSV는 기능을 비교하기 위한 공통 입력입니다. 각 노트북은 새 커널에서 독립 실행하고 API 실습은 자체 Session을 만듭니다. 이전 장의 출력·설정·도구는 자동으로 누적되지 않습니다. 장 도입부의 공통 예제·새 기능·이번 실습 조합을 확인하세요.

| 경로 | 권장 순서 | 선택 기준 |
| --- | --- | --- |
| 첫 실행과 핵심 개념 | 환경 준비 → 빠른 시작 → 1–5장 | API 흐름·Session·설정·파일 이해 |
| 기능 확장 | 6–11장 → 15장 | 의존성·업무 도구·재사용·승인·역할 분담 |
| 사내 배포와 운영 | 11장 → 12–14장 → 15장 | executor·사내 패키지·관측·복구 |
| Multi-agent 먼저 실습 | 3·5장 → 15장 | Session과 파일 지식으로 역할 분담 경험 |

12–14장은 15장의 선행 조건이 아닙니다. 11장의 승인과 15장의 결과 통합을 조합하는 예제는 별도 선택 확장입니다.

| 11장 | 기본 보고서·승인/거절 결과·승인 시 로컬 등록 | 애플리케이션 정책·사용자 callback |

7장의 목표 조회와 9장의 분석 재사용은 각각의 기능에 집중합니다. 10장에서 두 기능을 묶고, 11장은 기본 보고서에 업무 승인을 적용합니다. 15장은 직접 읽는 목표 JSON으로 분담을 학습합니다. 최종 응답의 확장 객체와 기본 분석 요약 파일은 같은 구조라고 가정하지 않습니다.

## 12–14장 기본 환경과 선택 확장

| 장 | 기본 API 경로 | 별도 선택 실습 |
| --- | --- | --- |
| 12장 | Self-hosted Docker executor | 로컬 패키지·Skill 점검 |
| 13장 | 새 OpenAI-hosted Session + 메모리 OTel | Collector·로컬 Hook 프로토콜 재생 |

13·14장은 12장의 executor를 이어 쓰지 않습니다. 관측·복구의 기본 실습과 별도 Docker 실행 증거를 구분합니다.

## 실행 모드

환경 준비와 1장은 실행 허용 스위치 없이 로컬에서 동작합니다. 아래 RUN_LIVE 안내는 실제 API 실습에 적용합니다.

| 선택 | 동작 |
| --- | --- |
| `RUN_LIVE=False` | API 준비 셀에서 실행 안내와 함께 멈춥니다. API 키 없이 로컬 셀만 확인하려면 오프라인 검증기를 사용합니다. |
| `RUN_LIVE=True` | 프로젝트 키와 모델 설정으로 실제 API·sandbox를 사용합니다. 사용 비용이 발생합니다. |
| `RUN_DOCKER=True` | 12–14장의 선택 로컬 Docker 실습입니다. 12장 실연결에는 이 설정과 전용 executor 키도 필요합니다. |
| 오프라인 검증기 | `requires_api` 셀을 제외하고 로컬 셀을 실행합니다. 실제 API 사용 권한이나 응답을 확인하는 검사는 아닙니다. |

노트북 직접 실행과 검증 실행 도구는 구분합니다. 직접 실행은 API 흐름과 결과를 보여 주며, 검증 실행 도구는 사본에서 정답·실행 증거·자원 정리를 추가로 확인합니다. 설정과 자원 정리 helper가 API 실행 루프를 대신하지 않습니다.

## 결과 읽기

빠른 시작의 입력은 숫자 3개이며 합계는 60입니다. 본문 CSV는 6행·판매 수량 11·총매출 127,500이며, 목표 조회 예제는 목표 150,000·달성률 0.85를 사용합니다. 보고서에서는 달성률을 85%로 표시합니다.

root Turn의 `completed`는 작업 종료 상태입니다. 계산값·실제 도구 실행·다운로드 파일·자원 삭제는 각각 확인합니다. 모델이 파일을 만들었다고 설명하는 것만으로 다운로드가 완료된 것은 아닙니다. 필요한 파일은 세션 정리 전에 내려받습니다.

`usage=None` 또는 `null`은 미보고이며 숫자 0과 다릅니다. usage는 best-effort 정보이고 실제 청구액이나 비용 상한을 검증하는 기능이 아닙니다.

### 분석 요약·검증 기록·생성 기록

| 명칭 | 대표 경로 | 생성 주체·의미 |
| --- | --- | --- |
| 분석 요약 | downloads/summary.json | 에이전트가 계산한 매출 결과를 내려받은 파일 |
| 검증 기록 | &lt;run_id&gt;/summary.json | 검증 runner가 실행 사본에서 만든 성공/실패·정리 결과 |
| 자원 생성 기록 | &lt;run_id&gt;/creation.json | 수동/자동 실행의 소유 자원 조사·복구용 metadata |
| 업무 승인 영수증 | 11장 등록 폴더의 .approval.json | 승인된 보고서 바이트와 사용자 결정의 연결 |

같은 summary.json 이름도 전체 경로와 생성 주체로 구분합니다. 수동 실습에서는 분석 요약을 읽을 수 있지만 runner 전용 검증 기록은 생성하지 않습니다. 업무 승인 영수증은 검증 runner의 receipt와 다른 결과입니다.

## 정리와 복구

각 실습은 자신이 생성한 세션과 Agent만 정리합니다. 세션 삭제와 sandbox의 물리적 정리가 같은 시점에 완료된다는 의미는 아닙니다. 프로세스를 강제로 종료하면 `finally`가 실행되지 않을 수 있습니다.

직접 실행의 `creation.json`과 저장한 Session·Turn ID로 상태를 확인한 뒤 복구합니다. 검증 도구로 실행했다면 같은 실행 폴더의 `summary.json` 검증 기록도 참고할 수 있습니다. 연결이 끊겼다는 이유만으로 같은 입력을 새 세션에 즉시 재전송하지 않습니다.

## 15장 Multi-agent 종합 실습

`uv run --group dev python scripts/run_multi_agent.py`는 API 셀을 제외하고 실행합니다. `--live`는 실제 모델·sandbox를 사용하며 두 하위 에이전트의 생성 이벤트·완료 Turn·성공한 담당별 Python 명령과 네 결과 파일을 확인한 뒤 세션을 삭제합니다. 단순히 모델이 두 담당을 언급하거나 정답을 출력한 것만으로 성공으로 표시하지 않습니다. 동시 실행 상한은 실제 병렬 실행 시간이나 성능 개선을 보장하지 않습니다.
